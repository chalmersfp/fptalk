title: "Dependent Type Providers and Error Reflection in Idris"

F#'s type providers are a practical and powerful means of gaining the benefits
of a modern static type system when working with data schemas that are defined
outside of the programming language, such as relational databases. F# type
providers are implemented using a form of compile-time code generation, similar
to Template Haskell, which requires the compiler to expose an internal API and
can lead to malformed types.

With dependent types, it is possible to define a type provider mechanism that
does not rely on code generation. Using this mechanism, a type provider becomes
a kind of generic program that is instantiated for a particular external
schema, which can be represented using an ordinary datatype. Because these
dependent type providers use the ordinary abstraction mechanisms of the the
type system, they preserve its safety properties.

However, the type errors resulting from this approach are not always
particularly understandable. Like embedded DSLs, errors resulting from
violation of provided types should be understandable by end users and not leak
details about the underlying implementation. A new Idris feature, called error
reflection, can be used to present more understandable error messages from type
providers.

In this talk, I present dependent type providers, explain their semantics, and
then demonstrate ongoing work on error reflection and how it can be used to
improve errors resulting from type providers.

Bio:
David Christiansen is a PhD student at the IT University of Copenhagen.  He is
interested in domain-specific languages, functional programming, programming
tools, and dependent types as a practical tool for writing software.
