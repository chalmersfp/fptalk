Agent workflows built around large language models are today authored either in graphical tools (e.g., n8n, Langflow, LangGraph Studio) or in low‑level code frameworks (e.g., LangGraph) whose composition primitives are add_node/add_edge over untyped dictionaries. Neither medium offers the disciplines we expect of production software: static typing, code review, testability, or principled reasoning about trust boundaries. This talk argues for Agents as Code, by analogy with Infrastructure as Code, and presents an embedded domain specific language (DSL) in which an LLM workflow is a first‑class typed value. As an invariant, the wire graph is fixed at plan‑construction time and remains statically inspectable — thus mitigating prompt injection attacks. Furthermore, common patterns (like prompt chaining, routing, evaluator–optimizer, bounded iteration) become ordinary combinators over the term algebra. The DSL has a single interpreter that runs the same plan against Ollama or any OpenAI‑compatible backend. The DSL also enables to implement a security‑by‑construction discipline, e.g., by encoding the Dual‑LLMs security pattern.

This is work in progress. The talk will also discuss future directions, including information-flow control and controlled run-time re-writing as a typed foundation for self-improving agents.
